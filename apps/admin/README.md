# Admin · 本地视频资料库

管理 API、媒体读取和后台任务位于 `apps/admin/`，Vue 管理界面位于 `apps/admin-web/`。默认配置、数据库、诊断日志仍从仓库根目录解析，与启动命令所在目录无关；复核状态默认随数据库保存为 `<数据库>.reviews.json`。首次安装请先阅读 [安装与配置](../README.md)。独立分享入口为 `node apps/admin/share.ts`（在仓库根目录执行）。

## 可选的本机域名与 macOS 自启动

作者个人环境的固定入口为 `https://youyin-server.home.zqzyz.com`，通过现有 Caddy 转发到 `127.0.0.1:3001`，沿用家庭服务的 Tailscale 访问限制。后台由 `com.zq.douyin-library` LaunchAgent 常驻，登录后启动，异常退出后重启，不依赖 SSH 转发或终端窗口。长时间导入不按页面访问空闲时间停机；重启保留已导入内容和断点，但继续导入仍需当前分享码。

本机启动配置 `deployment/com.zq.douyin-library.plist` 不进入代码库；其安装副本位于 `~/Library/LaunchAgents/`，日志位于仓库 `logs/library-server.launchd*.log`。迁移到其他机器时先调整绝对路径。修改启动配置后需重新加载 LaunchAgent；正在导入时先点击停止，待任务结束后再重启。

`LIBRARY_TRUSTED_ORIGINS` 是额外允许的完整源地址，以逗号分隔，不支持通配符。反向代理保留 Host 和 Origin，HTTPS 终止后的请求只接受精确配置的同源地址；其他域名和跨源管理请求仍拒绝。此设置不代替反向代理的访问限制。页面打开只读取状态，不自动启动异常扫描或清理。

## 分享与导入

导航中的「分享 / 导入」可以在实例之间传递作者、作者主页链接、作品及本地媒体。分享默认关闭，启动后在独立后台线程中生成固定清单，并开放单独的只读端口。其他实例填写地址和临时分享码后，先查看差异，再导入缺失内容。分享端只提供清单和已登记文件，不开放资料库管理、下载更新或删除接口；Cookie、浏览器资料和完整配置不在分享范围内。请在可信局域网使用。

- 作者按 UID/sec_uid 识别，昵称和目录名不作为去重身份。作者可以没有链接，也可以尚无本地作品；已关联的链接必须指向清单中的作者。导入只保留有关联作品的作者，当前记录与历史留存记录合并判断；仅有昵称或链接、没有任何作品记录的作者会跳过，旧预览也遵守该规则。账号当前被封禁或主页显示零作品不影响已留存历史记录，缺少媒体的历史作品仍会分享及导入其元数据。
- 导入以接收端为主：作者和作品已存在就复用，文件已存在则跳过；作品记录已有但缺视频、图片、音乐或其他附属文件时只补缺。文件移动后仍按作品 ID 和文件角色识别，不重复下载。重复导入、重试和中断续传不产生重复记录或文件。
- 本地同一角色已有不同内容时不覆盖、不自动另存副本，在差异清单中列出。导入保留本地真实作者资料；占位昵称和缺失 UID 可按同一作者身份补全，不会把“未命名作者”写入已有真实昵称。已有链接的启用状态保持不变；是否把新增、已关联的链接加入下载配置可单独选择。
- 文件以 SHA-256 校验，支持 HTTP Range 断点续传。临时文件位于下载根目录的 `.library-import/`，校验完成后以不覆盖现有文件的方式发布。逐作品登记，不把未完成的传输标为已下载；停止或断网后可继续。源清单变化时先重新预览，同一内容的断点仍可复用。
- 作者、链接和导入附属文件索引保存在作品数据库旁的 `*.library.sqlite`，文件指纹另存于 `*.library.sqlite.fingerprints.sqlite`，导入预览及最后任务保存在 `.library-transfer/`。分享码不持久保存；重启后继续导入需要填写当前地址和分享码。缓存和任务文件不进入 Git。
- 「包含清理前新版库中仍有文件的作品」只读取当前数据库目录下 `cleanup-backups/*/dy_downloader.before.db` 中的 `aweme` 记录，为活动库已移除的作品补全仍存音乐和不同版本的归属；不会读取旧版 `Release/data.db`。文件未能关联到作品时会显示未归属数量，未归属文件不默默计入已分享或已导入。
- 分享可选全部资料、指定作者或作品。默认空闲 15 分钟停止，传输进行中延后停止；手动停止立即关闭服务。导入与更新、删除等修改操作互斥，浏览可继续。哈希不同不代表损坏，首版不自动做有损媒体等价判定，也不会自动清理分享端。

本地拷入的作品使用 `local-` 加内容 SHA-256 前 32 位作为独立作品 ID，归档作者可使用“本地上传”，无需抖音主页链接。JSON 标明本地来源、原文件名和 SHA-256；真实作者及发布时间未知时留空，占位头像明确标注为生成图片。此类作品同样参与分享、导入和去重。已整理的历史未归属项以导入预览的 `unassignedResolutions` 记录，原分享清单和冲突记录保留；异常页仅在对应本地作品、文件索引与实际文件仍存在时将其计为已归档。

Windows 的后台传输使用 Node.js 24.12+；即使用 Bun 启动资料库，也会自动调用 PATH 中的 `node`（可用 `LIBRARY_NODE_PATH` 指定）。这样避开旧版 Windows Bun 的续传及线程退出兼容问题。

也可只启动分享服务，不启动资料库管理页面：

```powershell
node share.ts --config ../../config.yml --include-history
# 或 bun share.ts --config ../../config.yml --include-history
```

可用 `--port 12345` 固定分享端口，`--idle-minutes 15` 设置空闲时间。普通资料库仍按下文方式启动。新机器先按 [安装与配置](../README.md) 创建 Python 环境、配置和空数据库。

## 启动与浏览

在仓库的 `apps/` 目录用 Bun 安装依赖，管理服务用 Node.js 24.12+ 启动。

```sh
cd apps
bun install --frozen-lockfile
bun run build
bun run --filter @zqdouyin/admin start
```

Vite 将管理界面构建到 `apps/admin-web/dist/`，Hono 通过现有域名托管页面和 `/_admin/` 静态资源。更新前端后在 `apps/` 重新运行 `bun run build`，浏览器刷新即可读取新产物。开发时在 `apps/` 运行 `PORT=3001 bun run --filter @zqdouyin/admin start`，另开终端运行 `bun run --filter @zqdouyin/admin-web dev`。Vite 在 `http://127.0.0.1:5173` 提供页面，把 `/api/`、`/media/` 和旧媒体 `/assets/` 请求转发给管理端。

`@zqdouyin/python-bridge` 统一选择解释器，组装更新、链接检测、登录、本地扫描命令，处理子进程输入、输出和停止。可用 `PYTHON_EXECUTABLE` 覆盖解释器，默认优先用仓库的 `.venv`。任务进度和状态由管理端保存。

打开 `http://127.0.0.1:3001`。默认读取仓库根目录 `config.yml` 中的 `database_path` 和 `path`。作品和作者从 SQLite 加载，浏览时只检查当前页和详情需要的文件。下载完成后刷新页面即可读取数据库里的新作品。

- **作品**按发布时间从新到旧排列，可按标题、作者、作品 ID、类型和下载来源筛选。在详情中播放视频、翻阅图集和查看本地副本。
- **文件清单**在作品详情里查看。作品目录显示子目录和文件，平铺下载只列出归属该作品的文件。清单包含文件名、类型、大小和所在目录。
- **作者**基于数据库中的作者 ID 和昵称归并，按各自最近一次作品下载更新时间排列。喜欢、合集等作品按数据库记录的创作者展示。作者总览和作者详情均可切换卡片与列表，分别勾选作者或作品进行批量删除。详情页的「删除链接」可确认并移除配置中匹配的作者主页链接。
- **异常处理中心**集中媒体异常、无作品作者、链接检查及导入差异。打开页面只读取已有状态和结果，不自动扫描、检测或清理。点击「扫描媒体异常」后才检查全库；无作品作者会同时核对当前库、新版历史库和待导入清单，只有三个范围都没有作品的作者才进入手动清理候选。链接可手动检测并勾选移除，作者和作品保留；导入版本差异与未归属文件只读取已有清单供人工核对。媒体异常支持勾选后批量复核，或预览其关联作品的完整清理范围。所有清理先预览再确认，执行时重新核对令牌和数据变化；导入、更新或其他清理期间不执行删除。复核时可保存备注，标记已处理或已忽略。已有复核的记录会在复扫后保留，已修复的可在「复扫已消除」查看。
- **链接管理**搜索、添加、编辑或移除下载器配置中的 `link` 条目。点击「保存配置」后，下载器下次启动时会读取新列表。可通过 `CONFIG_PATH` 指定编辑的配置文件。
- **打开抖音**侧栏按钮打开程序专用的浏览器登录测试窗口，再次点击会聚焦同一窗口。可手动检查网页、登录并选择保存登录信息；关闭后再启动更新或链接检测，避免同时占用同一资料目录。此窗口不运行作品抓取。专用资料目录保存在本机 `config/browser-profile/`，网页本地存储和登录选择会随资料目录保留；不要与个人 Chrome 的默认资料目录混用。
- **登录状态保存**浏览器运行时每30秒保存一次 Cookie，手动测试窗口每5秒保存一次，并在切换作者、正常关闭时保存。保存只读取浏览器 Cookie，不导出全站存储、不新建或切换页签、不刷新页面；网页本地存储、IndexedDB 和登录选择由专用资料目录保留。`config/cookies.json` 使用仅当前用户可读写的权限，资料目录仅当前用户可访问，均不进入 Git。旧版生成的 `config/browser-state.json` 不再更新或用于恢复登录。配置使用 `cookies: auto` 时下次运行会读取更新后的 Cookie。保存操作不额外请求抖音接口，不保证服务器会延长登录有效期，站点要求验证时仍需手动完成。
- **清除作者作品**在作者页点击「清除所有作品」，核对全部分页的本地文件清单后确认。此操作清除该作者的本地作品副本，保留下载链接和数据库作品记录，清空本地文件路径、下载时间及本地封面/头像/详情路径，并把关联下载队列重置为待下载。未下载的已发现作品也纳入状态重置。作品记录保留，未下载记录不会显示在本地作品列表中；下次手动更新可重新下载。此功能与会移除链接的「删除作者」分开，更新运行中不允许清除。文件清除失败时不提前重置数据库状态，可重新读取清单后重试。

外置盘删除会识别带 AppleDouble 文件头的 `._` 元数据文件，允许它随主文件被系统自动移除，不会因此以 ENOENT 中止；普通缺失文件、被替换的文件和符号链接仍会中止并提示具体相对路径。作品索引也会跳过这些元数据文件。删除结束会再次核对下载根目录，避免外盘断开或根目录被替换时误报成功。此前已部分删除的操作，请重新读取清单后继续。
- **链接检测**在链接管理中点击单条「检测」或「检测全部」，可随时停止。检测读取当前编辑列表，不保存或移除链接，不下载作品。结果区分正常、不可访问、访问受限、格式无效和待确认，并显示原因及时间，可按结果筛选。用户主页根据页面账号状态判断，作品/合集/音乐根据目标内容信息确认；无法可靠确认的类型、超时或验证受阻会保留为待确认。检测默认在后台浏览器运行，也可勾选显示浏览器；整轮复用同一个会话。相邻检测至少间隔5秒发起；访问异常时退避至10、20秒，连续3次访问异常或遇到安全验证、HTTP 403/429时停止本轮，剩余链接不作判断。这是保守的检测节奏，不代表平台公布的安全频率。页面访问失败会显示错误类型或网络错误码，不记录含敏感参数的完整异常。结果保留在当前服务进程内，检测与下载更新不能同时运行。
- **更新**读取已保存的链接，启动一轮下载。页面显示链接总进度、当前作者和处理阶段、本组作品进度、累计下载/跳过/失败数、最近文件字节进度、耗时和最后进度更新时间。总进度按链接计算，作品数量在抓取列表后确定。停止或失败后保留最后的进度和统计，也可查看起止时间及失败原因。关闭页面后任务继续运行。更新使用当前资料库的下载目录和数据库。

更新顺序为「从未尝试优先，其次按最近尝试时间从旧到新」，同时间保留配置顺序。`library_update_state` 表在资料库数据库中持久保存各目标的开始、结束时间和处理状态，失败、取消及强制退出后的目标也会轮换到后面，避免每次都从前几个作者开始；新版本首次更新参考已有下载历史排序。同一作者主页的查询参数、尾部斜杠不会分开计时，短链接不提前联网解析。这里只调整顺序，不自动跳过近期更新目标，也不改写配置。`cli/main.py` 的可选 `url_scheduler` 接口仅由 library runner 注入，普通 CLI 保留原顺序；此项属于 library-only 差异，桌面端不需要此调度策略。

浏览器采集将滚动期间收到的作品响应纳入新增计数，滚动目标为作品列表的滚动容器。只有收到作品分页结束标志或达到用户配置的数量上限，才确认本次范围内的列表采集结束；连续无新增、达到滚动/时间上限及中途异常都保留已取得的作品，并提示「列表可能未取全」。作者主页的标称作品数只用于对照，不作为强制抓取数量，也不能单独证明列表被截断。

每轮滚动先等待1.2秒，未收到新作品时继续检查，单轮最多等待8秒；收到新作品或分页结束标志就继续处理，连续8个无新增轮次才停止。页面 ID 提取仅限作者作品列表区域，不从整页 HTML 或推荐区收集 ID，避免把无关作品的详情请求失败算到当前作者。已知不属于目标作者的页面条目不会再次补拉详情。空列表会区分明确的分页结束与访问失败，错误保留主页/分页 HTTP 状态、未登录或验证提示及安全的导航错误码。切换作者时清空上一位作者的提示，避免旧失败提示跟随到正在正常下载的作者。

共创作品的主作者可能是另一人。普通分页结束后额外观察页面4秒，每400毫秒检查一次作品卡片，接住主页延迟补充的共创作品，不额外发起滚动。浏览器会记住从目标作者作品接口或目标主页作品列表卡片取得的作品 ID，凭此确认归属，不再仅因主作者不同而丢弃共创；没有目标列表依据的其他作者条目仍被过滤。归属依据在切换作者时清空。`post` 下载将数据库和清单记录归入目标作者，原始 JSON 保留作品主作者信息；喜欢等其他来源仍按创作者入库。`download_pinned` 单独控制是否下载置顶，与共创判断无关。本机未找到桌面兄弟仓库，本次共享逻辑修复未同步到桌面端。

一次正文读取/JSON解析失败不会立即截断页面，程序继续等待后续有效分页，并记录 HTTP 状态、响应类型和安全的错误类别。预检请求不作为作品分页响应。网页明确显示「服务异常」时停止整批更新（退出码5），不把作者判成失效；浏览器关闭或启动失败也停止整批，避免继续请求其余作者。

资料库更新的 `post` 模式支持边抓列表边下载：API 或浏览器每取得一页作品，过滤、去重和登记后送入最多64条的内存队列，最多3个下载任务并行处理（配置并发数小于3时遵从配置）。队列满时暂停继续翻页；暂停等待下载的时间不占浏览器的主动采集时间预算。当前作者的列表和下载都处理结束后才切换作者，浏览器仍在整批任务中复用。其他下载模式保留原流程。

`download_queue` 表保存待下载、下载中、已完成及失败状态；`aweme` 表中的发现记录没有文件路径，不会误算为已下载。每个作品下载成功后立即登记文件，停止时保留未完成记录。下次更新同一作者且下载设置不变时优先恢复待下载作品，恢复前刷新详情以取得新的媒体地址；连续3次详情刷新失败则转由浏览器新抓取的页面详情接续，仍无法恢复的记录继续保留并提示。过滤或输出设置不同的队列按范围隔离。作品数会随抓取增长，页面分别显示列表状态、已处理数、正在下载数和等待数，在列表仍抓取时不显示作品完成百分比。

更新页按当前作者分别显示“已获取 / 新作品 / 已下载 / 已存在”，旧记录缺媒体或附属文件时单列“待补全”；仅列表中已去重的作品计入已获取，符合条件且尚未保存的计入新作品，成功保存后才计入已下载。页面顶部的下载与跳过统计属于整轮更新。更新状态保存在作品数据库同目录的 `library-update-status.json`，服务重启后保留最终结果；中断任务只提示手动继续，不会自动启动下载。旧版运行中任务未上报细分计数时显示“待核对”，保留已有累计结果。

资料库增量更新根据“接口作品总量－本地实际保存数量－本轮已接收待下载的缺失作品数”判断是否继续翻页，缺失作品按 ID 去重且遵守筛选条件。剩余差额大于5条时继续翻页；差额不超过5条、达到或超过总量时，当前页非置顶作品尾部已保存即可结束分页，已经接收的新作品和修复任务仍处理完再切换作者。例如本地88条、接口100条，首批20条中前9条缺失、后11条已保存：补齐本批后只差3条，下载这9条后结束，不再翻后面的历史。若本批只有6条缺失，剩余差额仍为6条，则继续翻页。页尾仍缺文件时继续，不把未下载的新作品当作已保存边界。

总量缺失时，有本地已保存作品的作者同样按已保存页尾增量停止，避免每轮重新遍历全部历史；没有可核实的本地作品时完整抓取。统计按目标作者的作品 ID 去重，并检查实际文件；其他作者、缺文件及只有元数据的记录不计入本地已保存数量。本地保留的历史作品可能多于主页，不会据此删除或对齐本地数量。小差额容忍可能跳过旧页深处少量缺失作品；需要补查时设 `incremental_page_stop: false`，保留下载去重并完整遍历。

优先使用已确认的主页总量 `_homepage_work_total`，其次使用作者资料接口的 `aweme_count`，均只接收非负整数。后者仅为分页参考，不视为已验证包含全部共创作品的精确总量，不据此宣称本地已完整。API 与浏览器采集使用同一停止条件，仍遵守显式设置的数量、时间和媒体筛选限制。先恢复历史待下载任务，当前已入队的任务处理完成后再进入下一作者；空页、纯置顶页不会触发停止；文件缺失、空文件或图集缺图不会被当作已保存的页尾。作品数量与分页边界统一只判断主视频或完整图集；缺 JSON、封面、头像或音乐不再降低本地作品数量、不再触发历史翻页，这些附件问题保留在手动媒体异常扫描中。新作品仍按所选输出设置下载附件。开启评论或转录时保留原流程，以免遗漏其独立补全任务。`increase.post: false` 的强制下载不会提前停止。此优化仅用于资料库启用的流式更新，普通 CLI 采集方式保持现状。

资料库下载更新不再自动扫描整个媒体根目录。优先查询作品数据库登记的路径，并验证文件存在且非空；需要兼容外部拷贝、移动或旧文件名时，只查询最近一次手动扫描保存的登记结果。未命中时正常下载，不触发全盘兜底；新下载、导入、删除继续由各自流程维护作品数据库。下载成功只更新本轮内存记录，重启后直接查数据库；强制下载和直接调用资产下载也不会建立全库索引。普通 CLI 保留原有自动兼容扫描，本库 runner 通过 `main_async(automatic_local_media_scan=False)` 显式关闭。

在“数据异常 → 媒体异常”点击“扫描更新本地文件”，才遍历媒体目录。扫描在独立进程执行，可查看目录项/媒体文件进度或停止；与下载、导入和其他修改互斥。结果保存在当前数据库的 `library_local_media_files` / `library_local_media_roots`，没有自动过期或自动刷新。只登记非空主媒体，排除封面、头像、音乐附件、AppleDouble 和符号链接；旧版截断文件名保留严格的日期/标题匹配。对已有作品补齐或修复失效的媒体、JSON、封面和头像路径，保留 Mac 已有效的路径、作者和历史资料；修改前的路径保存在 `library_local_media_repairs`。扫描不删除文件或作品，不访问抖音，不根据猜测创建未知作者；无法确认归属的 ID/文件仅在完成统计中报告。结果在完整扫描及磁盘身份核对后原子发布，失败或取消保留上次已发布结果。换盘后不复用其他磁盘的登记；命中登记也复核实际文件，删除后的旧记录不会让缺失文件被误判为存在。

这次变更涉及 `storage/local_media_registry.py`、`core/downloader_base.py` 和 CLI 的资料库运行参数；本机未找到桌面兄弟仓库，尚未同步该仓库。阶段日志继续保存在 `logs/library-update/*.jsonl`。

分页策略日志 `post_incremental_policy` 记录总量来源、本地实际保存数量和是否允许按已有页停止，便于核实翻页原因。

资料库服务、目录工作线程、分享/导入/异常处理进程及下载更新、链接检测、登录浏览器子进程默认启用应用层 I/O 全量诊断，日志位于仓库 `logs/io-audit/`。每次操作记录配对的 `begin` 与 `end`/`error`，包含 ID、父操作、UTC 时间、进程/线程、路径或无查询参数的 URL、调用位置、耗时及可获得的状态码/字节数。更新日志还关联当前作者、链接和阶段，包括增量停止判断。记录文件打开/读取/写入/检查/目录遍历/复制/移动/删除，SQLite 执行/取行/事务（异步调用另记排队至完成耗时），aiohttp/httpx/urllib、Node HTTP/fetch 和浏览器上下文内请求，以及 Playwright 异步动作、等待和 WebSocket 帧大小。HTTP 响应头与正文读取分开记录，便于区分等待响应和下载数据。

日志不记录文件内容、请求/响应正文、Cookie、Authorization、SQL 参数或展开后的 SQL；SQL 仅记录类型和模板哈希，URL 移除用户密码、查询参数和片段，浏览器脚本不记录内容或参数。每个进程/线程独立分卷，约64 MiB一卷，日志文件权限为600；不采样、不自动删除旧卷。Python 使用独立写入线程；跨度较长的操作保留开始时的作者归属，WebSocket 在失败、关闭或页面导航结束时补齐生命周期记录。预期的文件探测未命中、已存在目录和浏览器探测请求仍保留原始事件，在汇总中与异常分开。Node 小批量写入，批次达到512 KiB即落盘以限制同步扫描期间的内存占用。日志自身的 I/O 排除，避免递归。全量记录会增加 CPU、磁盘写入和空间占用；`LIBRARY_IO_AUDIT_DIR` 可指定日志目录，`LIBRARY_IO_AUDIT=0` 可临时关闭，修改后重启相应进程。

只读汇总所有日志或指定本轮文件：

```sh
.venv/bin/python apps/admin/scripts/analyze-io.py
.venv/bin/python apps/admin/scripts/analyze-io.py --pattern '*-updater-*.jsonl' --json
```

文件核对在同一次快照中复用公共目录解析、文件状态和图集列表；下一次核对重新检查，避免删除后的文件沿用旧结果。

汇总列出操作次数、累计/最长耗时、最慢调用位置、最近异常、预期探测/中止、未配对操作分类和覆盖提示；并发与嵌套耗时不能直接相加。未配对可能表示仍在执行、分卷缺失或进程被强制终止，末尾半行会单独计数。覆盖的是这些应用进程发起的 I/O；SQLite、Chromium、FFmpeg 等原生引擎内部的物理块读写、缓存命中、浏览器自身后台流量及其他程序操作不属于应用层日志。旧日志无法补录；已有分析日志仍保留在 `logs/library-update/`。新增 `utils/io_audit.py` 为资料库诊断模块，本机未找到桌面兄弟仓库，未同步该仓库。

“数据异常 → 日志清理”提供手动日志清理。先选择全部已结束或1/7/30天前的日志，点击“查看日志清理范围”，核对文件数量、大小与样例后确认永久删除。仅处理 `logs/io-audit/` 和 `logs/library-update/` 内格式明确的运行日志；保留当前运行任务的所有分卷、服务输出、未知文件、符号链接及诊断报告。删除前重新核对范围、文件身份和磁盘目录身份；发生变化则要求重新预览。可以在更新运行时清理其他已结束任务的日志，不自动清理，也不触碰作品、媒体或数据库。

资料库更新另外维护以下持久状态（普通 CLI 默认不启用）：

- `library_media_state` / `library_author_counts`：由 SQLite 触发器维护主媒体的登记数量，Python 下载与 Node 导入、删除共用；首次仅从现有数据库登记路径，不遍历硬盘。登记数量不等于逐文件验证数量；当前抓取页仍检查主视频或图集，外部复制、移动、删除后使用“扫描更新本地文件”更新登记。完整性未知与已确认缺失分别记录，历史作品和路径不会因缺失而删除。
- `library_post_audit`：按作者及筛选配置记录参考总数、登记数、历史差额、本轮页数与收到数量、历史最远核对日期、预算状态和手动重核标记。采集达到预算也会保留明确的“历史待复核”，不会宣称已取全。后续自动更新从首页检查新增；若尾部已存在，且扣除上次核对过的历史差额后新增差额不超过5条，则下载本批缺失作品后结束作者。总数减少或本地多于主页时同样保留本地历史作品。未恢复的下载队列、显式强制下载及评论/转录回填仍阻止提前结束。
- 默认作者资料等待20秒、首批作品等待20秒、历史采集90秒。已取得作品进入下载队列后的实际下载等待不占历史预算；这些预算不保证总下载时间小于90秒。可在下载器 YAML 中设置 `library_profile_timeout_seconds`、`library_first_page_timeout_seconds`、`library_history_timeout_seconds`。作者不可访问或超时仅记录失败/待复核；遇到安全验证则停止批次等待手动处理。

“数据异常 → 运行诊断”打开时只读取上次保存的结果；点击“刷新运行诊断”汇总最近8轮轻量阶段日志和数据库状态，不读取全部 I/O 日志、不扫描媒体、不访问抖音。页面展示作者耗时、页数、登记/参考总数、新作品/下载数、继续翻页或停止原因，可按作者和状态筛选。历史差额可标记“下次更新重核历史”，失败作者可标记“下次更新优先重试”；按钮不立即启动抓取，下次正常更新才执行。取消手动重核的运行会保留重核标记。这里保存核对范围和待复核差额，不通过未经验证的接口游标跳过页面。

## 永久删除

在作品详情点「删除作品」，或在作者详情点「删除作者」。在作者详情可勾选作品后点「批量删除作品」，在作者总览可勾选作者后点「批量删除」。翻页和切换视图会保留勾选。确认页面会显示涉及的作品和文件，删除作者时还会显示匹配的配置链接数量。删除作品会永久删除数据库关联的本地媒体文件，并清理媒体已缺失的对应数据库记录。删除作者会永久删除所选作者的作品副本和对应数据库记录，并移除其匹配的配置链接。

删除前会重新核对清单。操作期间如果遇到文件占用或路径变化，会中止并刷新索引。已永久删除的文件无法通过资料库恢复。索引继续跳过旧版本留下的 `.catalog-trash`。
